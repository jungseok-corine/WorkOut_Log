1. App Overview & Core Concepts

1.1 What is WorkOut Log?

WorkOut Log is a privacy-first iOS workout tracking application that allows users to record exercise sessions, track sets (weight × reps), and visualize training volume trends over time. The app is built entirely offline with zero data collection, using SwiftData for local persistence.

1.2 Key Features

  • Session Management: Create workout sessions with dates and notes
  • Set Tracking: Record exercise name, weight (kg), and repetitions
  • Auto-Calculated Volume: Volume = weight × reps (e.g., 100kg × 10 = 1000kg volume)
  • Exercise Library: 7 muscle group categories (Lower Body, Upper Body, Cardio, Core, Full Body, Arms, Shoulders)
  • Trends & Analytics: Daily (≤10 days), Weekly (8 weeks, Sunday-Saturday), Monthly (6 months)
  • Personal Records (PR): Track 1RM using Epley formula
  • Accessibility: Full VoiceOver support, Dynamic Type, high contrast

1.3 Tech Stack

Component Technology Notes
Language Swift 6 Strict concurrency mode enabled
UI Framework SwiftUI Declarative UI with @Observable ViewModels
State Management Observation Framework Replaces @ObservableObject/@Published
Persistence SwiftData Local-only, no iCloud sync (optional backup)
Charts Swift Charts Native Apple framework for data visualization
Architecture Clean Architecture 3-layer: Presentation → Domain ← Data
Testing XCTest Unit tests + UI automation tests
Core Philosophy

This app prioritizes user privacy and architectural purity. The Domain layer has ZERO imports of SwiftUI or SwiftData, ensuring business logic remains framework-independent and highly testable.

2.3 Layer Responsibilities

Presentation Layer

  • SwiftUI views and navigation
  • @Observable ViewModels (state management)
  • User interaction handling (button taps, form input)
  • UI state (loading, errors, success messages)
  • Allowed imports: SwiftUI, Domain entities/use cases

Domain Layer (Pure Swift)

  • Business entities (structs/enums only)
  • Use cases (business logic operations)
  • Repository protocols (abstract data access)
  • Forbidden imports: SwiftUI, SwiftData, Charts
  • Goal: Framework-independent, 100% unit testable

Data Layer

  • SwiftData @Model classes
  • Repository implementations (RepositoryImpl)
  • Domain ↔ Data mappers
  • ModelContext management
  • Allowed imports: SwiftData, Foundation, Domain protocols
Critical Rule

The Domain layer must NEVER import SwiftUI or SwiftData. If you find yourself writing import SwiftUI in a Domain file, you're violating Clean Architecture principles.

3. SwiftData Models & CRUD Operations

3.1 SwiftData Model Example

import SwiftData
import Foundation

@Model
final class ExerciseModel {
    @Attribute(.unique) var id: String
    var name: String
    var mainRaw: String  // ExerciseCategoryMain.rawValue
    var lastUsedDate: Date?

    init(id: String, name: String, mainRaw: String, lastUsedDate: Date? = nil) {
        self.id = id
        self.name = name
        self.mainRaw = mainRaw
        self.lastUsedDate = lastUsedDate
    }
}

3.2 Data Relationships

WorkoutSession (1) ─────────── (N) SetRecord ↓ ↓ │ exerciseID │ ↓ └─────────────────────────→ Exercise (1) Relationship Strategy: • SwiftData uses ID-based references (not @Relationship) • Each SetRecord stores sessionID and exerciseID as Strings • Queries join data by filtering on these ID fields

3.3 CRUD Examples

Create (Insert)

func upsert(_ exercise: Exercise) async throws {
    let exerciseID = exercise.id
    let predicate = #Predicate<ExerciseModel> { $0.id == exerciseID }
    var descriptor = FetchDescriptor<ExerciseModel>(predicate: predicate)
    descriptor.fetchLimit = 1  // ⚠️ Property, not constructor param

    if let existing = try context.fetch(descriptor).first {
        // Update existing
        existing.name = exercise.name
        existing.mainRaw = exercise.main.rawValue
    } else {
        // Insert new
        let model = ExerciseModel.fromDomain(exercise)
        context.insert(model)
    }

    try context.save()  // Persist to disk
}

Read (Fetch with Predicate)

func fetch(by id: String) async throws -> Exercise? {
    let exerciseID = id
    let predicate = #Predicate<ExerciseModel> { $0.id == exerciseID }
    var descriptor = FetchDescriptor<ExerciseModel>(predicate: predicate)
    descriptor.fetchLimit = 1

    guard let model = try context.fetch(descriptor).first else {
        return nil
    }

    return model.toDomain()  // Convert to Domain entity
}

Update (Modify Existing)

// Fetch → Modify → Save pattern
let predicate = #Predicate<WorkoutSessionModel> { $0.id == sessionID }
var descriptor = FetchDescriptor<WorkoutSessionModel>(predicate: predicate)
descriptor.fetchLimit = 1

if let session = try context.fetch(descriptor).first {
    session.notes = "Updated notes"
    try context.save()
}

Delete

func delete(id: String) async throws {
    let exerciseID = id
    let predicate = #Predicate<ExerciseModel> { $0.id == exerciseID }
    var descriptor = FetchDescriptor<ExerciseModel>(predicate: predicate)
    descriptor.fetchLimit = 1

    if let exercise = try context.fetch(descriptor).first {
        context.delete(exercise)
        try context.save()
    }
}

3.4 SwiftData Constraints & Gotchas

SwiftData KeyPath Limitations

❌ FORBIDDEN (will crash at runtime):

  • \.name.localizedLowercase — Value-type member chaining
  • \.name.lowercased() — Method calls on value types
  • #Predicate { $0.name.contains("search") } — Case-sensitive only

✅ ALLOWED:

  • \.name — Stored properties only
  • \.id
  • \.lastUsedDate

Solution: Fetch all, then filter client-side with .filter { $0.name.localizedStandardContains(query) }

FetchDescriptor.fetchLimit is a Property

Unlike Core Data, SwiftData's FetchDescriptor.fetchLimit is NOT a constructor parameter. 

// ❌ WRONG
let descriptor = FetchDescriptor<ExerciseModel>(
    predicate: predicate,
    fetchLimit: 10  // Compile error!
)

// ✅ CORRECT
var descriptor = FetchDescriptor<ExerciseModel>(predicate: predicate)
descriptor.fetchLimit = 10  // Set as property

4. ViewModel Pattern with Observation Framework

4.1 @Observable (iOS 17+)

The Observation framework replaces @ObservableObject and @Published with a simpler @Observable macro. Changes to properties are automatically tracked, and SwiftUI views re-render when observed state changes.

4.2 ViewModel Example

import Foundation
import Observation

@Observable
@MainActor
final class TrendsViewModel {
    var trendData: [VolumeTrendPoint] = []
    var scope: TrendScope = .daily
    var selectedCategory: ExerciseCategoryMain?
    var showAllDays: Bool = false
    var isLoading: Bool = false

    private let computeTrendUseCase: ComputeVolumeTrendUseCase

    init(computeTrendUseCase: ComputeVolumeTrendUseCase) {
        self.computeTrendUseCase = computeTrendUseCase
    }

    func onAppear() {
        Task {
            await loadTrends()
        }
    }

    func scopeChanged() {
        Task {
            await loadTrends()
        }
    }

    func categoryFilterChanged() {
        Task {
            await loadTrends()
        }
    }

    private func loadTrends() async {
        isLoading = true
        do {
            trendData = try await computeTrendUseCase(
                scope: scope,
                categoryFilter: selectedCategory,
                includeZeroDays: showAllDays
            )
            isLoading = false
        } catch {
            print("Error loading trends: \(error)")
            isLoading = false
        }
    }
}

4.3 SwiftUI View Integration

struct TrendsView: View {
    @State var vm: TrendsViewModel  // ⚠️ Use @State, not @StateObject

    init(viewModel: TrendsViewModel) {
        _vm = State(initialValue: viewModel)  // Underscore syntax
    }

    var body: some View {
        VStack {
            // Scope picker
            Picker("Scope", selection: $vm.scope) {
                Text("Daily").tag(TrendScope.daily)
                Text("Weekly").tag(TrendScope.weekly)
                Text("Monthly").tag(TrendScope.monthly)
            }
            .onChange(of: vm.scope) { _, _ in
                vm.scopeChanged()
            }

            // Chart
            if vm.isLoading {
                ProgressView()
            } else {
                Chart(vm.trendData) { point in
                    LineMark(
                        x: .value("Date", point.date),
                        y: .value("Volume", point.volume)
                    )
                }
            }
        }
        .task {
            vm.onAppear()
        }
    }
}
@MainActor Requirement

ViewModels must be annotated with @MainActor to ensure all state updates happen on the main thread. This is required for SwiftUI reactivity.

5. Trends Calculation (Daily/Weekly/Monthly)

5.1 Volume Definition

Volume = weight (kg) × repetitions

Example: 100kg × 10 reps = 1000kg volume

5.2 Trend Specifications

Scope Period Max Points Zero Days? Notes
Daily Last 30 days ≤10 Optional (toggle) Two-line labels: month / day
Weekly Last 8 weeks 8 Yes (always) Sunday-Saturday buckets, day-range labels
Monthly Last 6 months 6 Yes (always) Single-line labels (e.g., "Oct")

5.3 Weekly Bucket Calculation

Weekly trends use Sunday-Saturday calendar weeks (not Monday-start ISO weeks). This aligns with typical user workout planning. 

private func makeCalendar(for scope: TrendScope) -> Calendar {
    switch scope {
    case .weekly:
        // Sunday-Saturday weeks (firstWeekday = 1 means Sunday)
        var calendar = Calendar(identifier: .gregorian)
        calendar.firstWeekday = 1
        return calendar
    case .daily, .monthly:
        // ISO 8601 for other scopes (Monday-start)
        return Calendar(identifier: .iso8601)
    }
}

5.4 Daily Trend Capping (≤10 Points)

// Generate all points from last 30 days
let allPoints = volumeByPeriod.keys.sorted().map { periodStart in
    VolumeTrendPoint(
        date: periodStart,
        volume: volumeByPeriod[periodStart] ?? 0,
        periodLabel: formatter.string(from: periodStart)
    )
}

// For daily scope: cap to latest 10 points
if scope == .daily {
    return Array(allPoints.suffix(10))  // Keep last 10 only
} else {
    return allPoints
}

5.5 Category Filtering

// Apply category filter during volume aggregation
for set in sets {
    if let filter = categoryFilter {
        if let exercise = try await exerciseRepo.fetch(by: set.exerciseID) {
            if exercise.main != filter {
                continue  // Skip sets not matching filter
            }
        }
    }
    volumeByPeriod[periodStart, default: 0] += set.volume
}
Accessibility: Two-Line Axis Labels

Daily and Weekly trends use custom two-line x-axis labels for clarity:

  • Daily: Top = "Oct" (abbreviated month), Bottom = "9" (day)
  • Weekly: Top = "Oct" (month), Bottom = "6–12" (day range for Sun–Sat)
  • VoiceOver: Combined label reads "October 9th" or "October 6 to October 12"

Implementation uses AxisValueLabel(content: { }) to force ViewBuilder overload.

7. Common Errors & Solutions

7.1 SwiftData KeyPath Chaining Error

Runtime Crash
SwiftData/Schema.swift:336: Fatal error: Invalid KeyPath name.localizedLowercase
on ExerciseModel points to a value type: String but has additional descendant

Cause

SwiftData's #Predicate and SortDescriptor only support stored property KeyPaths. Chaining to computed properties or methods on value types (like \.name.localizedLowercase) is forbidden.

❌ WRONG CODE

let predicate = #Predicate<ExerciseModel> { model in
    model.name.localizedLowercase.contains(query)  // CRASH!
}

let sort = [SortDescriptor(\.name.localizedLowercase)]  // CRASH!

✅ CORRECT FIX

// Fetch all, then filter client-side
let sort = [SortDescriptor(\ExerciseModel.name, order: .forward)]
var descriptor = FetchDescriptor<ExerciseModel>(sortBy: sort)
descriptor.fetchLimit = 200

return try context.fetch(descriptor)
    .filter { $0.name.localizedStandardContains(query) }  // Client-side!
    .map { $0.toDomain() }

7.2 AxisValueLabel Overload Ambiguity

Compile Error
Type '() -> ()' cannot conform to 'StringProtocol'

Cause

Swift's overload resolution chooses the String-based initializer instead of the ViewBuilder content initializer when using trailing closure syntax AxisValueLabel { }.

✅ SOLUTION

// ❌ WRONG (ambiguous overload)
AxisValueLabel {
    if let date = value.as(Date.self) {
        VStack {
            Text(date, format: .dateTime.month(.abbreviated))
            Text(date, format: .dateTime.day())
        }
    }
}

// ✅ CORRECT (explicit content parameter)
AxisValueLabel(content: {
    if let date = value.as(Date.self) {
        VStack {
            Text(date, format: .dateTime.month(.abbreviated))
            Text(date, format: .dateTime.day())
        }
        .accessibilityLabel(date.formatted(.dateTime.month(.wide).day()))
    }
})

7.4 ViewBuilder Assignment Statement Error

Compile Error
Cannot assign value inside @ViewBuilder closure

Cause

SwiftUI's @ViewBuilder closures cannot contain assignment statements (e.g., let a11yLabel: String = ...) directly. Assignment must happen before the ViewBuilder or inside an if let.

✅ SOLUTION

// ❌ WRONG (assignment inside ViewBuilder)
AxisValueLabel(content: {
    let a11yLabel: String = "October 9th"  // ERROR!
    VStack {
        Text("Oct")
    }
    .accessibilityLabel(a11yLabel)
})

// ✅ CORRECT (assignment inside if let)
AxisValueLabel(content: {
    if let date = value.as(Date.self) {
        let a11yLabel: String = date.formatted(.dateTime.month(.wide).day())
        VStack {
            Text(date, format: .dateTime.month(.abbreviated))
        }
        .accessibilityLabel(a11yLabel)
    }
})

8. Glossary of Terms

Term Definition
Set A single execution of an exercise (e.g., Bench Press 100kg × 10 reps)
Reps (Repetitions) Number of times an exercise is performed in one set
Volume Weight × Reps (e.g., 100kg × 10 = 1000kg volume)
Session A complete workout on a specific date (contains multiple sets)
Exercise A named movement (e.g., Squat, Bench Press, Deadlift)
Category Muscle group classification (Lower Body, Upper Body, Cardio, etc.)
PR (Personal Record) Your best performance for a given exercise (usually heaviest weight or highest 1RM)
1RM (One-Rep Max) Maximum weight you can lift for one repetition
Entity Domain layer business object (struct/enum)
Use Case Encapsulated business operation (e.g., CreateSession, ComputeVolumeTrend)
Repository Data access abstraction layer (protocol in Domain, implementation in Data)
ViewModel Intermediary between View and Domain, marked with @Observable
Model SwiftData persistent object (class marked with @Model)
DI (Dependency Injection) Pattern where dependencies are provided to objects rather than created internally
